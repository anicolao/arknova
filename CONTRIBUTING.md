# Contributing

## Initial-review workflow

All project changes use a pull request for initial review. Do not leave completed
work only in a local branch and do not commit directly to `main`.

For every change:

1. Create a focused branch from the current `main`.
2. Commit the intended change and its verification artifacts.
3. Push the branch to the shared GitHub repository.
4. Open a draft pull request as soon as the change is ready for initial review.
5. Keep subsequent review fixes on the same branch and push them to the same PR.
6. Mark the PR ready only after automated checks pass and any required manual
   verification is either recorded or clearly identified as outstanding.

This workflow applies to implementation, documentation, tests, tooling, and
workflow changes. A contributor may skip it only when the project owner
explicitly requests a different workflow for that particular change.
